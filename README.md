# Tochka · Точка выбора

**Выбор ИИ-моделей на задачах вашего бизнеса.** Исследовательский CLI-прототип 0.5.2.

Компания задаёт задачи, документы, эталоны и критерии. Tochka получает ответы нескольких конфигураций через API, проверяет их отдельной моделью-судьёй и выбирает подходящие по качеству, полноте проверки, времени и стоимости. Численные ответы тоже оценивает судья. Ошибки и пропуски остаются **неизвестными**, а не нулевым качеством или бесплатным выполнением.

## Установка одной командой · Linux и macOS

Собственный Python-движок входит в пакет; Node.js/npm не нужны. Нужны интернет и `curl`; установщик подготавливает Python через uv. Подходит для Linux, включая Omarchy, и macOS.

```bash
curl -fsSL https://raw.githubusercontent.com/ignatnovichenko/Tochka/main/install.sh | sh
```

Откройте новый терминал и запустите `tochka`. Внутри: `/` — меню восьми действий, `/settings` — настройки и API-ключи. Собственный движок входит в Python-пакет; `/setup --check` проверяет его состояние. Установщик также напечатает полный путь для немедленного запуска.

Не нужны заранее установленные Python, Node.js, Git или OpenCode. Установщик использует [uv](https://docs.astral.sh/uv/guides/tools/), при необходимости загружает Python 3.11 и устанавливает закреплённую версию Tochka в изолированное пользовательское окружение. После установки Python-пакета он автоматически выполняет локальную проверку `tochka setup --check`, без дополнительных загрузок движка. `sudo` не используется. Установщик добавляет папку команд в настройки оболочки; отключить это можно через `sh install.sh --no-modify-path`. Модельные запросы при установке не выполняются.

[Скачать установщик и пакет из Releases](https://github.com/ignatnovichenko/Tochka/releases/latest) · [Подробная установка, обновление и удаление](docs/INSTALL_RU.md)

Поддерживаемые цели: Linux x86_64/ARM64, macOS Apple Silicon/Intel. CI проверяет Linux x86_64, macOS ARM64 и Intel; результаты каждого запуска доступны во вкладке Actions. Windows пока не поддерживается этим установщиком.

## Установка из исходников для разработки

Python 3.10+ (проверено на 3.11). Собственный API-движок использует стандартную библиотеку Python:

```bash
git clone https://github.com/ignatnovichenko/Tochka.git
cd Tochka
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[spreadsheet]'
tochka setup
tochka
```

Ядро не требует внешних Python-библиотек. Дополнение `spreadsheet` нужно для исторического табличного модуля и полного набора тестов. Без установки пакета: `python -m nir_eval.app wizard`. Старый вход `python -m nir_eval experiment ...` сохранён.

## Интерактивная консоль

Запустите `tochka`, введите `/` и нажмите Enter: появится меню с номерами действий. Выберите номер либо напишите slash-команду сразу. Меню `/` описывает все команды; `/run --help` показывает аргументы запуска, аналогично работает `--help` у остальных команд. `/exit` закрывает консоль; Ctrl+C прерывает текущее действие.

- `/experiment` — создать через мастер, подготовить демонстрационный набор или открыть эксперимент.
- `/settings` — задачи и документы, критерии, модели, судья, ограничения, API-ключи и модель помощника.
- `/run` — показать план, запустить новый прогон или продолжить прежний в новой папке.
- `/results` — результаты, HTML-отчёт и пересчёт выбора с другими ограничениями без новых API-вызовов.
- `/calibrate` — проверить судью на размеченных примерах.
- `/doctor` — проверить готовность движка, описать проблему и получить помощь.
- `/update` — обновить Tochka из GitHub; после успешного обновления запустите CLI заново.
- `/exit` — выйти.

Для обычной работы достаточно пути `/experiment` → `/settings` → `/run` → `/results`. Меню показывает восемь действий. Детальные команды сохранены для скриптов и доступны напрямую, например `/solver-add ...`, `/setup --check` и `tochka keys`.

Обычные команды с аргументами сохраняются: например, `/run my-test --output runs/new --allow-remote`. Меню использует те же команды. Без интерактивного терминала `tochka` выводит справку. Исходные задачи, настройки и прогоны не становятся обычным чатом с моделью: запрос к помощнику выполняется через `/doctor`.

### Диагностика и исправления

`/doctor` спрашивает, что произошло, проверяет Python, синтаксис исходников, состояние ключей и выбранного эксперимента. Для модельного анализа используется модель помощника из `/settings`, а если её нет — модель-судья выбранного эксперимента (или первая solver-модель). Сам факт наличия ключа не определяет модель. Сменить её можно в `/settings` → «Модель помощника диагностики».

Перед отправкой показываются модель и адрес API. После подтверждения выполняется один запрос с описанием, техническими статусами и ограниченным набором исходников. Задачи, документы и сохранённые ответы не загружаются; известные ключи маскируются. Исходники берутся из локальной установки проекта: открытость репозитория сама по себе не даёт модели знания кода.

Помощник может предложить до трёх точечных изменений разрешённых Python-файлов. Программа проверяет пути, неизменность исходников и синтаксис, показывает diff и применяет его только после подтверждения. До записи создаётся резервная копия; ошибка записи вызывает откат уже записанных файлов. Произвольные shell-команды, изменение ключей и исторических результатов не выполняются. Отчёт и копии находятся в `~/.local/state/tochka/doctor` (учитывается `XDG_STATE_HOME`). После применения нужно перезапустить CLI и повторить проблемное действие: проверка синтаксиса не доказывает исправление поведения.

Модельная диагностика требует работающего API и расходует его лимиты. Она не снимает ограничения провайдера, не восстанавливает отозванный ключ и не гарантирует ремонт любой ошибки. В установке без исходного проекта помощник даёт рекомендации без правки кода. Если CLI вообще не может импортироваться, встроенный `/doctor` тоже может быть недоступен. Только локальные проверки: `tochka doctor --local-only`. Модельная часть проверена тестовыми ответами, не живым Go-вызовом.

## Подготовка модельных запросов

Прогоны, матрицу моделей, конфигураций, задач и повторов исполняет **собственный Python-движок Tochka**. Он вызывает OpenAI-compatible Chat Completions API напрямую; отдельный Node.js/npm runtime не нужен.

```bash
tochka setup --check
```

В консоли — `/setup`. Это локальная диагностика, без загрузки зависимостей и модельных вызовов. Новые конфигурации автоматически используют собственный движок, выбора движка нет. Исторические конфигурации и статистика Promptfoo сохраняются как доказательства прежних прогонов; новый backend не переписывает их результаты.

Собственный планировщик ограничивает число одновременных запросов. Ответы сохраняются по мере завершения. Отдельные раунды судьи и разрешённых исправлений JSON сохраняют строгую проверку критериев, бюджет вызовов и учёт неизвестной стоимости/качества. Автоматические транспортные повторы и кэш отключены.

[Историческая интеграция Promptfoo 0.4–0.5](docs/PROMPTFOO_SETUP_RU.md) · [Историческое сравнение](docs/PROMPTFOO_COMPARISON_RU.md)

## Мастер эксперимента

Мастер последовательно предлагает:

1. Создать демонабор или импортировать задачи/рубрики из JSONL, добавить UTF-8 документы.
2. Настроить API-адреса, модели, параметры и имя переменной ключа.
3. Выбрать отдельную модель-судью и допустимое число исправлений её невалидного JSON.
4. Задать минимальное качество, полноту проверки, максимальное время и стоимость.
5. Выбрать параллельность, просмотреть план количества запросов и оценку расходов, затем сохранить настройки или явно подтвердить запуск.

**Enter на последнем шаге сохраняет настройки без запуска.** Внешние API вызываются только после явного согласия в мастере или `--allow-remote` в команде `run`/`calibrate`/`resume`.

## Только API

Новые прогоны используют OpenAI-compatible **Chat Completions**: `POST <base-url>/chat/completions`. Поддержаны локальные HTTP-серверы и внешние HTTPS API. Запуск OpenCode CLI, shell-команд или загрузка Transformers через приложение отключены. Старые исходники и результаты сохранены для воспроизводимости истории, но не служат текущим способом подключения.

Самый простой способ: выполните `tochka keys` и выберите «добавить». Для OpenCode Go достаточно задать название подключения и вставить ключ скрытым вводом; адрес и имя ключа можно оставить по умолчанию. Он будет сохранён для следующих запусков на этом компьютере, пока вы его не удалите.

```bash
tochka keys                 # список и меню добавления/удаления
tochka keys list            # список с замаскированными значениями
tochka keys add go          # скрытый ввод ключа OpenCode Go
tochka keys delete go       # удалить из Tochka
tochka keys show go         # показать полный ключ в терминале
```

Для другого API: `tochka keys add company --base-url https://api.example.com/v1 --api-key-env COMPANY_API_KEY`. Укажите тот же адрес и имя ключа в настройках моделей. Заменить существующее подключение: `tochka keys add go --replace`.

Отсутствующий ключ также запрашивается при подтверждённом запуске из мастера или команд `run`, `calibrate`, `resume` и сохраняется локально. Отмена или пустой ввод останавливают запуск. Список скрывает значения; `show` раскрывает ключ только по явной команде и только в терминале.

Хранилище: `~/.config/tochka/credentials.json` (или `$XDG_CONFIG_HOME/tochka/credentials.json`). На Linux и macOS папка имеет права `0700`, файл — `0600`. Это локальный файл **без шифрования**, доступный вашему пользователю, а не облачное хранилище. Он не включается в проект, отчёты или GitHub и не переносится автоматически на другой компьютер. Ключ привязан к адресу API и имени переменной. Удаление из Tochka не отзывает ключ у провайдера и не удаляет подключение из OpenCode или окружения.

Без интерактивного терминала скрытый ввод не выполняется: используйте сохранённый ключ или задайте переменную окружения заранее. Это также удобно для автоматизации. Например, в Bash можно ввести ключ без вывода на экран и записи самого ключа в историю:

```bash
read -rsp 'API key: ' TOCHKA_API_KEY
export TOCHKA_API_KEY
printf '\n'
```

В мастере укажите `TOCHKA_API_KEY`. Не вставляйте ключ в URL, JSON, README или чат.

Если вы уже подключили **OpenCode Go** через `/connect`, мастер обнаружит локальное подключение и предложит API Go автоматически. Оставьте адрес `https://opencode.ai/inference/go/openai/v1` и имя `OPENCODE_GO_API_KEY`: при отсутствии этой переменной и собственного сохранённого ключа Tochka прочитает активный ключ Go из локального хранилища OpenCode. Ключ не копируется в настройки или результаты; сохранённый ключ автоматически используется только для указанного адреса Go. Явно заданная переменная имеет приоритет. Поддержаны текущая таблица `credential` в `opencode.db` и прежний `auth.json`; формат хранилища может меняться при обновлении OpenCode.

Настройка API: [docs/API_RU.md](docs/API_RU.md). Исторические результаты планировщика Promptfoo: [реальный сквозной прогон 0.5.0](docs/PROMPTFOO_SCHEDULER_RESULTS_RU.md). История предыдущей версии сохранена в [отдельном отчёте](docs/PROMPTFOO_LIVE_RESULTS_RU.md).

## Командный сценарий

Ниже конфигурация без модельных запросов; замените адрес и ID на данные вашего API:

```bash
tochka init my-test --demo
tochka solver-add my-test --provider api --base-url https://api.example.com/v1 --api-key-env TOCHKA_API_KEY --model solver-a --name direct --temperature 0 --max-tokens 512
tochka solver-add my-test --provider api --base-url https://api.example.com/v1 --api-key-env TOCHKA_API_KEY --model solver-b --name checked --instruction 'Проверьте факты и вычисления. Дайте готовый деловой ответ.' --max-tokens 512
tochka judge-set my-test --provider api --base-url https://api.example.com/v1 --api-key-env TOCHKA_API_KEY --model judge-model --max-tokens 2048 --max-calls 100 --structured-retries 1
tochka policy-set my-test --min-quality 0.8 --min-coverage 1 --min-pass-rate 0.9 --max-latency 30
tochka plan my-test
```

`plan`, `show`, `models --directory my-test` не отправляют запросов к моделям. Запуск после настройки и проверки цены:

```bash
tochka calibrate my-test --labels my-test/calibration.jsonl --output runs/my-calibration --allow-remote --concurrency 4
tochka run my-test --output runs/my-business --allow-remote --concurrency 4
tochka results runs/my-business
```

`--concurrency` задаёт максимум одновременных запросов: от 1 до 32, по умолчанию 4. Значение 1 оставляет тот же собственный движок с последовательным исполнением. Ограничение действует на всю текущую матрицу, включая разные модели; это не лимит запросов в минуту.

Для локального сервера используйте `--base-url http://127.0.0.1:8080/v1`; флаг `--allow-remote` не нужен. API должен возвращать `choices[0].message.content` и по возможности `usage`.

## Что пользователь получает после запуска

- **Терминал:** вывод о подходящих конфигурациях, оценка, сколько ответов проверено, время, стоимость и причина исключения.
- **`report.html`:** самостоятельный HTML-отчёт без внешних ресурсов; решение на первом экране, сравнение, ограничения и раскрывающиеся задачи с ответами и объяснениями судьи.
- **`comparison.csv` / `comparison.json`:** таблица для Excel и машинные данные.
- **Сырые записи:** промпты solver, ответы, token usage, время, оценки, цитаты, структурные ошибки и хеши.

Качество и полнота проверки показаны отдельно. «100% по 2 из 4 ответов» не скрывает две неизвестные оценки. По умолчанию отбор требует полного покрытия. Если вы явно снижаете требуемое покрытие, вывод предупреждает о неполных данных. При равенстве возвращаются все лидеры; если никто не подходит, отчёт прямо объясняет почему.

Время вызова модели и время судьи измеряются отдельно, без ожидания в очереди собственного планировщика. Время судьи включает разрешённые попытки исправления. Итоговое время — сумма этих измерений для задачи; это не длительность всего параллельного прогона и не чистая скорость токенов. Цена solver, judge и сумма показываются отдельно, когда известны. `usage.cost` считается сообщённой провайдером стоимостью; тарифные расчёты остаются оценками и не подменяют известную стоимость в жёстком ограничении. Месячная цена подписки в стоимость отдельного запроса не распределяется.

## Пересчитать ограничения без нового прогона

```bash
tochka reselect runs/my-business --min-quality 0.95 --max-latency 5 --output reports/strict
tochka reselect runs/my-business --max-cost 0.02 --output reports/budget
```

Создаются **новые** HTML/CSV/JSON. Исходные данные и статистика не меняются. Модельных вызовов нет. Остальные ограничения наследуются из исходного выбора; можно передать полную новую политику через `--policy policy.json`.

## Продолжить после прерывания или лимита

```bash
tochka resume runs/my-business --output runs/my-business-resumed --plan-only
tochka resume runs/my-business --output runs/my-business-resumed --allow-remote --concurrency 4
```

Продолжение создаёт новую папку. Используются сохранённые копии задач и настроек. Успешные ответы и валидные оценки переиспользуются; запрашивается только недостающее. Ошибки, исходные ответы и полная история остаются в `history/source`. При сохранённом `Retry-After` продолжение блокируется до указанного времени. Цена и время переиспользованных результатов не представляются как новые расходы; manifest разделяет reused/new работу.

При аварии сохранённые завершённые результаты доступны для продолжения. Для отправленных, но незавершённых заданий manifest фиксирует неопределённость: запрос мог уже достичь API, даже если событие начала не успело сохраниться. Их расходы неизвестны; повтор при resume может снова потратить лимит. При смешении старых и новых способов измерения время не считается сопоставимым автоматически.

Хеши, ID, промпты и входные данные проверяются перед продолжением. Повреждённые завершённые записи не принимаются. После аварии допускается только оборванная последняя незавершённая строка JSONL; её исходные байты сохраняются. Повторный запуск в существующую выходную папку запрещён.

**Исторические OpenCode CLI-прогоны 0.2.0 доступны для просмотра и пересчёта выбора, но не для автоматического продолжения:** переход на API меняет транспорт. Для них создайте новый эксперимент с API-настройками. Если запрос был выполнен сервисом, но компьютер выключился до сохранения ответа, гарантировать отсутствие повторного запроса нельзя: серверный idempotency API здесь не заявлен.

## Собственные задачи и документы

```bash
tochka init company-test
tochka rubric-add company-test --id returns --criterion 'facts=Ответ опирается только на правила возврата' --criterion 'action=Понятно следующее действие клиента' --critical 'false_promise=Выдуманы обещания или условия'
tochka task-add company-test --id return-001 --rubric returns --task 'Ответьте клиенту на запрос возврата' --context 'Покупка 5 дней назад; товар не использован; чек есть.' --document return-policy.txt --reference 'Возврат допустим при выполнении условий правил.'
```

`--document` можно повторять; поддерживается текст/Markdown UTF-8. PDF/DOCX сначала экспортируйте в текст. Эталоны и рубрики не передаются solver. Готовые наборы: `tochka import company-test --cases cases.jsonl --rubrics rubrics.jsonl`. Образцы — `nir_eval/demo/`.

[Исторические прогоны версии 0.4.0 / OpenCode Go · 11 ноября 2026](docs/PROMPTFOO_LIVE_RESULTS_RU.md): три выбранные модели, 6/6 валидных бизнес-оценок, отдельная калибровка 4/4 и полный учёт 46 запросов, включая неудачные подключения. Две задачи на модель не являются общим рейтингом качества.

Исторические реальные результаты сохранены **без изменений**: [RESULTS_RU.md](RESULTS_RU.md), `runs/current_business`, все калибровки и попытка после лимита. Это 4 задачи × 2 модели, 8 ответов; валидных судейских оценок 6/8. Контрольная калибровка 8/8 не доказывает общую точность судьи.

Автоматические тесты проверяют матрицы, параллельность, отдельные раунды судьи и восстановление, включая реальный **локальный HTTP-сервер с искусственными ответами**, полный API-цикл, стоимость, 429, продолжение, неизменность статистики и пересчёт без запросов. Эти fixtures не являются новыми модельными результатами. Результаты живых модельных прогонов фиксируются отдельно от этих программных проверок.

```bash
python scripts/check_all.py
python scripts/audit_current.py
```

Ограничения: небольшие синтетические примеры, зависимость от качества судьи, отсутствие GUI, потокового API и независимой статистической гарантии. `max_calls` ограничивает количество вызовов в каждом model run, а не денежный баланс; тарифы и неизвестное число токенов не позволяют обещать точный бюджет заранее.

## Продуктовое направление

[Концепция Tochka](docs/PRODUCT_VISION_RU.md): универсальный подбор конфигураций и маршрутизация моделей для AI-агентов в разных бизнес-процессах. Новый тип процесса инициирует сравнительную оценку, а её результаты становятся основой маршрута для последующих задач. Это направление развития, а не описание готовых возможностей MVP.

В пошаговом мастере модели выбираются номером из каталога API. Каталог загружается один раз для каждого подключения; судья выбирается отдельно от решающих моделей. Если каталог недоступен, остаётся ручной ввод ID. Наличие в каталоге не гарантирует доступность модели по квоте или правилам аккаунта.
