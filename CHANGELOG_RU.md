- Обновлены подсказки запуска, документация и установщик.

# Версия 0.5.0 · Прогоны и параллельность Promptfoo

- Матрицу всех моделей, конфигураций, задач и повторов теперь исполняет публичный `promptfoo.evaluate()`; HTTP-провайдер Promptfoo сохраняется. Второго движка и последовательного запасного пути нет.
- `run`, `resume` и `calibrate` принимают `--concurrency` от 1 до 32, по умолчанию 4. Параллельность доступна и в мастере; ограничение общее для текущей матрицы, включая разные модели.
- Ответы и оценки сохраняются по мере завершения. Отдельный судья исполняется параллельно; исправления невалидного JSON идут явными раундами через Promptfoo с прежними проверками критериев, цитат и бюджета вызовов.
- Время вызовов исключает очередь и запуск worker. Исторические записи сохраняют исходную область измерения; несовместимые измерения не используются как достоверное суммарное время.
- При прерывании сохраняются завершённые записи и сведения о незавершённых заданиях. Последние могли уже достигнуть API: их стоимость неизвестна, а продолжение не гарантирует отсутствие повторного расхода. Resume создаёт новую папку и сохраняет исходную историю.
- Бизнес-критерии, неизвестные оценки и цены, происхождение стоимости, отбор и HTML/CSV/JSON-отчёты остаются в Tochka. Кэш, автоматические транспортные повторы и отдельная история Promptfoo отключены.
- Установщик автоматически подготавливает совместимые Node.js/npm на Linux/macOS; установка через pip требует отдельной подготовки зависимостей и `tochka setup`.
- Добавлены проверки матрицы, параллельности, потокового сохранения результатов, исправлений судьи и продолжения. Живые модельные результаты публикуются отдельными артефактами; исторические прогоны 0.4.0 не переименовываются в результаты 0.5.0.

# Версия 0.4.0 · Promptfoo как единственный API-транспорт

- Все новые запросы solver, судьи и модельной диагностики выполняются через закреплённый HTTP-провайдер Promptfoo 0.125.1. Прежний Python API-транспорт удалён из исполняемого приложения; выбора движка нет.
- Команды `tochka setup`, `tochka setup --check` и `/setup` устанавливают или проверяют runtime. Для вызовов моделей нужны Node.js 22.22.0+ и npm; просмотр результатов и повторный отбор работают без Node.js.
- Установщик 0.4.0 проверяет Node.js/npm до установки, затем подготавливает Python-пакет и автоматически выполняет setup Promptfoo. При ошибке подготовки runtime он не сообщает об успешной установке. Установка из исходников через pip требует отдельного `tochka setup`.
- Существующие задачи, отдельный судья, проверка доказательств, бизнес-отбор и неизменяемое продолжение остаются в Tochka. Evaluator и планировщик матрицы Promptfoo не подключены.
- Сырой ответ API проходит общую нормализацию: неизвестная стоимость не равна нулю, тарифные и провайдерские оценки отделены от фактической цены. Ошибка судьи остаётся неизвестной оценкой.
- В адаптере отключены кэш, автоматические транспортные повторы и telemetry; добавлены изолированный worker, проверка его здоровья, ограничение размера ответов и сохранение идентификатора сессии. Историческая статистика не переписывается.
- Добавлены сравнение исходного кода Promptfoo/Tochka и инструкция установки. Итоги живых модельных прогонов фиксируются в отдельных отчётах; успешная установка runtime не подтверждает качество моделей.

# Версия 0.3.0 · 11 ноября 2026

- Интерактивный запуск `tochka`, меню `/`, полная `/help`, выбор модели `/model` и диагностика `/doctor` с просмотром исправлений, резервной копией и подтверждением. Модельная диагностика проверена искусственными ответами без реального inference.

- Продолжение прерванных API-прогонов в новой папке и повторный выбор по ограничениям без модельных запросов.
- Исходная статистика реальных прогонов сохранена без изменений. Новые проверки не являются новыми оценками качества моделей.

## История версии 0.2.0

# Изменения относительно исходного архива

- Новый `nir-eval experiment`: создание набора, JSONL-импорт, добавление задач и UTF-8 документов, критериев и критических ошибок, настройка моделей и независимого судьи, порогов, прогон, калибровка, результаты и повторный отбор без inference.
- Планировщик нескольких solver-конфигураций с общими задачами/рубриками/судьёй; сравнение с проверкой хешей, полноты и идентичности входов. Сохраняются все ничьи и причины исключения.
- Провайдер установленного OpenCode CLI: явный allowlist бесплатных ID, stdin, обычный профиль, single-step NDJSON, нативные токены и стоимость, timeout, cooldown по 429, запрет paid fallback и выдуманных generation parameters.
- Уточнение инструкции судьи для ID и точных цитат. Явно настраиваемые структурные повторы (default 0), общий бюджет учитывает дополнительные вызовы; trace, cost и latency сохраняют все попытки. Сетевые ошибки не повторяются.
- Стоимость solver+judge известна только при наличии обоих компонентов. Неизвестные quality/cost остаются null.
- HTML с раскрывающимися критериями и объяснениями; общий HTML/CSV/JSON. Не реализован отдельно предложенный новый дизайн бизнес-отчёта.
- Local HTTP solver исключён из системного proxy для localhost. Поддержка локальных серверов сохранена.
- Исправлены 2 тестовые XLSX-fixtures: XML `<v/>` поддерживается наряду с `<v></v>`; сам spreadsheet scorer не изменялся.
- Исходные исследования и результаты сохранены. Веса, venv, auth-файлы и ключи не входят в поставку.
