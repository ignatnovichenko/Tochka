# Третий запуск: генерация FinQA-DSL и локальный калькулятор

Отдельная, согласованная после run_02 конфигурация. Та же Qwen2.5-7B-Instruct Q4_K_M, тот же llama.cpp, тот же CPU, те же 12 dev-ID, greedy и максимум 192 новых токена. Поменялся протокол выхода: вместо готового численного answer модель должна выдать один JSON с FinQA DSL program.

Модель получает полные исходные тексты, таблицу и вопрос, а также описание допустимых операций и синтаксиса из неизменённого MVP `prompts.py`. Эталонные программы, числа ответа и supporting facts ей не передаются. Это однопроходная генерация программы, а не агент с обратной связью от инструмента.

Только синтаксически допустимые программы исполняются ограниченным локальным интерпретатором. Произвольный Python, eval/exec и внешний доступ не используются. Ошибки JSON, вложенные вызовы вместо последовательности FinQA, неправильное число аргументов, отсутствующие ссылки и другие нарушения не исправляются автоматически. Они входят в знаменатель как неуспех.

После генерации:

1. Строгая проверка полноты 12 ID.
2. Проверка prompt против исходного рецепта и разрешённых публичных полей.
3. Разбор JSON и DSL, локальное вычисление числа, сравнение round(predicted, 5) с canonical FinQA.
4. Для валидных программ дополнительная сверка числа с немодифицированным official evaluator и официальная Program accuracy.
5. Отдельные oracle/invalid controls, которые не считаются результатами модели.

Все исходные результаты run_01/run_02, gold и документы сохраняются без замены. Никакой отбор по успеху не выполняется. Известные оговорки исходной аннотации остаются в `dataset_audit.json`.

## Воспроизведение

```bash
OMP_NUM_THREADS=4 .venv/bin/python run_llama_benchmark.py \
  --limit 12 --seed 42 --protocols program --max-new-tokens 192 \
  --threads 4 --outdir rerun_03
.venv/bin/python score_local_run.py rerun_03
```

Требуется окружение и модель из RUN_02_PROTOCOL.md. Время замеряет локальный completion call; время исполнения калькулятора не входит в сохранённую latency генерации. Данная конфигурация не измеряет улучшение от циклической проверки/исправления программ, поскольку таких шагов нет.
