# Promptfoo в Tochka: установка и запуск

Все новые модельные запросы Tochka выполняются через HTTP-провайдер **Promptfoo 0.125.1**. Задачи, отдельный судья, проверка оценок, выбор конфигураций и отчёты остаются в Tochka. Планировщик матрицы Promptfoo в этой версии не используется.

Выбора движка нет. Прежний Python-транспорт удалён из исполняемого приложения; он не используется как запасной путь при ошибке Promptfoo. Исторические результаты сохраняются для просмотра и анализа.

Подключение моделей идёт через OpenAI-compatible Chat Completions API. Установка Promptfoo не предоставляет модели или API-ключи. **Node.js нужен для вызовов моделей; просмотр сохранённых отчётов и повторный отбор работают без него.**

## 1. Установить runtime

Установщик Tochka 0.4.0 (`install.sh`) проверяет Node.js/npm заранее и автоматически выполняет `tochka setup`. После его успешного завершения повторять установку runtime не требуется; используйте `tochka setup --check`. Для установки из исходников через pip или повторной подготовки runtime выполните команды ниже.

На Linux или macOS установите **Node.js 22.22.0 или новее и npm**. Они нужны дополнительно к обычной установке Tochka. Проверьте доступность в том же терминале:

```bash
node --version
npm --version
tochka setup
tochka setup --check
```

`setup` загружает зависимости через npm по сохранённому lock-файлу, без запуска npm lifecycle scripts, для выполнения модельных запросов. Новые конфигурации автоматически используют Promptfoo. Требуется доступ к npm registry. Runtime хранится в `~/.local/share/tochka/promptfoo-0.125.1` или под `$XDG_DATA_HOME`. При работе из исходников может использоваться подготовленный runtime внутри пакета.

`setup --check` проверяет версию Node.js, установленную версию Promptfoo и запуск worker с импортом библиотеки. Проверка здоровья не обращается к модели. Значение `ready: true` подтверждает работоспособность локального runtime, но не доступность API, ключа или выбранной модели.

В интерактивной консоли выполните `/setup`; проверка без установки — `/setup --check`. Отдельных параметров выбора движка нет.

Если Node.js/npm отсутствуют, сначала установите их и повторите `setup`. При ошибке загрузки проверьте соединение с npm registry. Диагностика не предлагает удалять задачи или результаты: они не находятся в каталоге runtime.

## 2. Подключить API-ключ

Для OpenCode Go:

```bash
tochka keys add go
```

Введите ключ скрытым вводом. Для другого провайдера используйте `--base-url` и `--api-key-env`, как описано в [README](../README.md#только-api). Для Go далее используются адрес `https://opencode.ai/inference/go/openai/v1` и имя ключа `OPENCODE_GO_API_KEY`. Идентификаторы доступных моделей берите у своего провайдера; судья должен отличаться от solver.

## 3. Создать эксперимент

Пример ниже создаёт синтетический демонабор. Замените два значения на реальные ID моделей своего аккаунта. Эти переменные содержат названия моделей, не ключи:

```bash
SOLVER_MODEL='ID_МОДЕЛИ_ИСПОЛНИТЕЛЯ'
JUDGE_MODEL='ID_ДРУГОЙ_МОДЕЛИ_СУДЬИ'

tochka init pf-demo --demo

tochka solver-add pf-demo --name baseline \
  --provider api \
  --base-url https://opencode.ai/inference/go/openai/v1 \
  --api-key-env OPENCODE_GO_API_KEY \
  --model "$SOLVER_MODEL" --max-tokens 2048 --max-calls 20

tochka judge-set pf-demo \
  --provider api \
  --base-url https://opencode.ai/inference/go/openai/v1 \
  --api-key-env OPENCODE_GO_API_KEY \
  --model "$JUDGE_MODEL" --max-tokens 8192 --max-calls 20 \
  --structured-retries 0

tochka policy-set pf-demo --min-quality 0.8 --min-coverage 1
tochka plan pf-demo
```

Настройка и просмотр плана не выполняют модельные запросы. Проверяйте число запросов в плане. `max_calls` ограничивает вызовы в одном model run, а не денежные расходы.

Запуск ниже **отправляет задачи внешнему API и расходует его лимит**:

```bash
tochka run pf-demo --output runs/pf-demo-001 --allow-remote
tochka results runs/pf-demo-001
```

Рядом с результатами появятся `report.html`, `comparison.csv` и `comparison.json`. Папка вывода должна быть новой.

## Что происходит со старыми экспериментами

Сохранённые результаты прежних версий не пересчитываются и не переписываются при установке Promptfoo. Их можно просматривать и повторно отбирать конфигурации по сохранённым данным без модельных запросов.

Чтобы перенести существующий эксперимент на Promptfoo без ручной правки JSON, создайте новый эксперимент и импортируйте прежние задачи и критерии:

```bash
tochka init pf-company
tochka import pf-company --cases old-company/cases.jsonl --rubrics old-company/rubrics.jsonl
```

Затем настройте solver и судью для `pf-company` командами выше, повторив нужные модели, параметры и политику отбора. `solver-add` не перезаписывает существующее имя конфигурации: попытка добавить то же имя завершится ошибкой. Старый эксперимент останется доступным для сравнения.

Не меняйте настройки в сохранённых `runs/.../inputs`. Продолжение использует исходные конфигурации и проверяет их хеши. Для переноса исторического эксперимента нужен новый прогон с заново созданными настройками, а не подмена данных старого результата. Старый транспорт не запускается.

## Какие гарантии сохраняются

- Worker использует публичный `loadApiProvider()` Promptfoo с HTTP-провайдером; логика матрицы, судьи и resume остаётся в Tochka.
- Ответ API передаётся общей функции нормализации Tochka. Отсутствующая стоимость остаётся неизвестной; оценка по тарифам не превращается в фактическую цену.
- Кэш и автоматические транспортные повторы отключены. Явные `structured-retries` судьи — отдельная настройка Tochka, учитываемая в лимите вызовов.
- Встроенные telemetry, sharing и сохранение истории Promptfoo не используются. Worker работает во временном каталоге; ключ не записывается в аргументы процесса или журналы. Результаты сохраняет Tochka.
- После 429 сохраняется срок следующей попытки. Продолжение записывает результат в новую папку и не изменяет исходную статистику.

Запуск worker и взаимодействие процессов добавляют накладные расходы. В метаданных сохраняются версия движка и его измерения времени; сравнение времени с историческими прогонами прежнего транспорта нужно интерпретировать с учётом этой разницы.

[Сравнение исходного кода и границы интеграции](PROMPTFOO_COMPARISON_RU.md). Примеры команд в этой инструкции не являются свидетельством успешного живого прогона: такие результаты должны сопровождаться отдельным отчётом.
