# OpenCode: текущая интеграция, 10.11.2026

Провайдер `type: opencode` реализован в `nir_eval/opencode.py`. Он использует установленную команду:

```
opencode run --model <explicit-free-id> --format json --title 'NIR evaluation' --archived
```

Промпт передаётся через stdin; рабочая папка временная и пустая. Профиль и штатный фоновый сервис остаются пользовательскими. CLI сам использует свою авторизацию. Прямой доступ к inference API, копирование auth-файлов, ротация аккаунтов и платный fallback отсутствуют. При необходимости вход выполняется пользователем через обычный `/connect` в OpenCode; ключ не требуется передавать программе НИР.

Установленная версия при тестировании: **2.2.6**. Обычные вызовы с явным выбором Big Pickle, MiniMax M3.1 Flash Free и GLM 5.3 Flash Free работают. Сочетание дополнительного project `opencode.json` (custom eval-agent, deny permissions, snapshots=false) давало `provider.free-limit` 429 — как в standalone, так и через background service. Без этой конфигурации вызовы снова проходили. Это диагностированное различие условий запуска, а не доказанная причина на стороне сервиса. Исходные сообщения 429 и успешные проверки описаны в `evidence/current_connection.json`.

Ранний адаптер `scripts/opencode_stdio_adapter.py` оставлен как исторический изолированный эксперимент для старого окружения и его offline tests. Его жёсткие пути `/workspace/shared/...`, pinned 2.2.7 и cooldown не используются новым провайдером. Старые JSON configs `*opencode.example.json` относятся к этому историческому адаптеру; для новой настройки используйте `experiment solver-add/judge-set`.

Разрешены только конкретные бесплатные ID из allowlist. Paid ID и неподдерживаемые параметры отклоняются до запуска CLI. Список сверялся с официальной таблицей: https://opencode.ai/docs/console/models/ (проверено 10.11.2026). Free-tier разрешён через OpenCode; прямой API не используется. Модели с отмеченными в документации региональными ограничениями Beam/Inkling не включены в allowlist.

Сохраняются текст ответа, session ID, hash NDJSON, native tokens, reported cost и причина завершения. `cost=0` записывается только когда CLI действительно вернул 0; отсутствие стоимости остаётся null. Любой неполный/невалидный поток, tool event или не-stop завершение — ошибка, не качественная оценка. При 429 записывается `.nir-opencode-cooldown.json`; последующие вызовы этого рабочего контекста прекращаются до указанного срока. Сетевых retries нет. Явно включаемые `structured_retries` относятся только к невалидному ответу судьи: новый оценочный вызов в том же бюджете с сохранением исходного результата, без ручной правки score/quotes.

Адаптер просит не пользоваться инструментами и отвергает tool events, но это не предотвращающий sandbox и не гарантия отсутствия побочных эффектов произвольного пользовательского профиля/плагина. В текущем эксперименте используются только синтетические бизнес-задачи; успешные ответы состоят из одного шага без tool events. Температура, seed и output-token limit через этот CLI не контролируются. Сравниваем реальные модели и явные инструкции, а не выдуманные настройки.
