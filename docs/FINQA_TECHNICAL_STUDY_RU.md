# НИР: воспроизводимая оценка LLM на бизнес-задачах

Работающий исследовательский MVP, а не готовый промышленный продукт. Он запускает локальную или совместимую модель, сохраняет ответы, автоматически проверяет их и строит таблицу результатов. Публичный FinQA измеряет финансовые вычисления по тексту и таблицам; отдельный модуль SpreadsheetBench проверяет результаты редактирования XLSX.

## Что действительно выполнено

- **Настоящий сравнительный пилот:** 12 одинаковых задач FinQA dev × 2 протокола × 2 конфигурации, **48 вызовов локальных моделей**, плюс отдельный исследовательский DSL-пилот 7B на тех же 12 задачах: **60 benchmark-попыток**. Qwen2.5-0.5B-Instruct: direct **0/12**, CoT **0/12**. Qwen2.5-7B-Instruct-GGUF Q4_K_M: direct **3/12**, CoT **3/12**. Результаты не отбирались и эталоны не менялись.
- 0.5B direct/CoT: разобраны 10/12 и 6/12 ответов; средняя задержка 5.421/11.292 с, медиана 4.407/7.965 с.
- 7B direct/CoT: разобраны 11/12 и 12/12; средняя задержка 48.760/65.189 с, медиана 50.890/63.726 с.
- **Времена между моделями не являются контролируемым speed comparison:** 0.5B измерял только `torch.generate`, 7B — полный llama.cpp completion; различаются размер, dtype/квантование и runtime. Внутри одного прогона границы таймера одинаковы.
- Wilson 95%: 0/12 → **0–24.2%**, 3/12 → **8.9–53.2%**. Межмодельный exact McNemar p=0.25 для каждого протокола; общее превосходство не установлено. Это малый dev-пилот, не финальный test.
- Независимый scalar scorer подтвердил все 48 оценок; сообщения и отрендеренные prompts совпали во всех 24 парах. Ручной аудит обнаружил возможные неоднозначности исходной разметки, сохранённые без исправления канонических результатов.
- **DSL + калькулятор:** 7B выдал 11/12 JSON, но только 2/12 исполнимых FinQA-программ; правильна 1/12 (8.3%, Wilson 1.5–35.4%). Официальные execution и symbolic program accuracy также 1/12. Автоматического repair/обратной связи нет. Это дополнительная конфигурация после двух исходных прогонов, а не полный факторный план.
- **57 автоматических тестов** основного пакета и XLSX-адаптера прошли.
- Безопасный интерпретатор совпал с эталонными итогами всех **883 dev** и **1 147 test** задач FinQA. Это проверка оценщика, **не результаты LLM**.
- SpreadsheetBench: **912 задач, 2 729 пар**. Контроль на первых 10 задачах: 24/30 эталонных XLSX сравнимы и совпадают, 6/30 не оценены из-за отсутствующих кешей формул в самих эталонах. Реального XLSX-агента пока нет.

Открыть готовую сравнительную таблицу: `runs/model_comparison_with_program/report.html`. Русское резюме: `runs/model_comparison_with_program/COMPARISON_RU.md`. Машинные результаты лежат рядом в JSON/JSONL/CSV. Исходные ответы, параметры и manifests: `evidence/qwen_0_5b/` , `evidence/qwen_7b/` и `evidence/qwen_7b_program/`. Исходное сравнение 48 попыток сохранено отдельно в `runs/model_comparison/`.

## Быстрый старт без модели, ключей и платежей

Python 3.10+. Для ядра FinQA дополнительные зависимости не нужны.

```bash
cd mvp
python -m nir_eval --help
python -m unittest discover -s tests -p test_core.py -v
python -m nir_eval validate data/finqa_dev.json
python -m nir_eval plan --config configs/finqa_oracle.json --output runs/prompts.jsonl
python -m nir_eval run --config configs/smoke_oracle.json --output runs/my_smoke
```

Последняя команда запускает **oracle-control на синтетических тестах**, не модель. Она проверяет конвейер и должна дать 100%. Нельзя представлять этот процент как качество LLM. Для повторного запуска используйте новый каталог или `--resume`; завершённые попытки не выполняются снова.

Для XLSX и полного набора тестов:

```bash
python -m pip install '.[spreadsheet]'
python -m unittest discover -s tests -v
python -m nir_eval spreadsheet --help
```

Копия FinQA dev включена для переносимости; она содержит эталоны. Модели получают только `question`, `pre_text`, `table`, `post_text` через разрешающий список полей. Не отправляйте ей исходный JSON целиком.

## Подключение настоящей модели

### Локальный OpenAI-compatible сервер

Отредактируйте `configs/local_openai_example.json`: задайте реальный ID модели и адрес своего сервера. Сервер должен быть запущен отдельно.

```bash
python -m nir_eval run --config configs/local_openai_example.json --output runs/local_model
```

Поддерживаются ответы Chat Completions, `usage`, `finish_reason` и версия ответа модели. Таймауты, HTTP-ошибки и ошибки формата входят в знаменатель. TTFT не измеряется. Ключ задаётся только через переменную окружения, названную в `provider.api_key_env`; по умолчанию `NIR_API_KEY`.

Внешние HTTPS-провайдеры заблокированы без `--allow-remote`. Этот флаг сам по себе **не гарантирует бесплатность и не заменяет проверку условий, разрешение передавать данные или авторизацию расходов**. В выполненном эксперименте внешние платные API не использовались.

### Локальный Transformers

Адаптер `transformers-local` загружает модель один раз, только с диска, с `local_files_only=True` и `trust_remote_code=False`. Никакие файлы автоматически не скачиваются. Инструкция и зависимости: [docs/LOCAL_MODELS_RU.md](docs/LOCAL_MODELS_RU.md).

### Свой исполняемый адаптер

`configs/command_example.json` запускает доверенную команду без shell. JSON запроса приходит в stdin, stdout содержит `{"text":"...","usage":{...},"metadata":{...}}` или непосредственно текст ответа. Передаются `messages`, `model`, `parameters`, `id`, `config`, `repetition`. Процесс запускается на каждую попытку; для тяжёлых моделей лучше HTTP-сервер или встроенный локальный адаптер.

`replay` нужен для отладки и отмечается `replay-not-inference`. Он **не** создаёт новые измерения качества/скорости модели.

## Протокол и проверка

- `direct`: только JSON с ответом.
- `cot`: JSON с краткими шагами вычисления и итогом.
- `program`: JSON с программой в ограниченном DSL FinQA. Программа интерпретируется безопасно, без `eval`, `exec`, Python, файловой системы или сети.
- Выбор задач: сортировка SHA-256 строки `seed:id`; по умолчанию seed=42. Все конфигурации получают одинаковые ID.
- В каждом record: модель, конфигурация, повтор, параметры, hash prompt, raw output, разобранный ответ, эталон, правильность, задержка, доступные токены и ошибки.
- Численные ответы сравниваются после округления результата до 5 знаков с `qa.exe_ans`. Проценты в строках трактуются как доли; автоматического выбора «удобного» множителя 100 нет.
- Разметка FinQA местами неоднозначна по шкале процент/доля; канонический scorer не исправляет её задним числом. Для содержательных выводов нужен ручной аудит ошибок и отдельная метрика, заранее зафиксированная до теста.
- Формат JSON строгий: произвольный текст до/после, несколько объектов, дубли ключей и NaN отвергаются. Допускается одна JSON code fence. Число строкой можно разобрать, поэтому parseable-answer не тождественно строгому соблюдению запрошенной JSON-схемы.
- `program_exact_match` означает совпадение токенов, **не официальную symbolic program accuracy**.
- Ошибки не удаляются из знаменателя. Слепого отбора лучших ответов и скрытого LLM-судьи нет.
- Интервалы по задачам учитывают, что повторы одной задачи не независимы. Wilson в таблице использует только первый повтор каждой задачи; дополнительный cluster bootstrap хранится в JSON.

Подробнее: [docs/METHODOLOGY_RU.md](docs/METHODOLOGY_RU.md).

## Воспроизводимость и результаты

```bash
# Повторная проверка уже выполненного реального прогона, без нового inference:
python -m nir_eval import-results \
  --records evidence/qwen_0_5b/records.jsonl \
  --manifest evidence/qwen_0_5b/manifest.json \
  --dataset data/finqa_dev.json --output runs/recheck_qwen

# Перестроить таблицы из уже оценённых записей:
python -m nir_eval report runs/recheck_qwen/records.jsonl --output runs/recheck_qwen
```

Импорт проверяет окончание прогона, точное покрытие ID × конфигурации × повторы, SHA-256 датасета, модель/revision и совпадение записанных prompt с текущим leakage-safe шаблоном. Сохраняются оригинальные задержки и токены. Импорт не называется новым inference; подлинность исходных логов определяется их источником, а не одним названием поля provenance.

`manifest.json` фиксирует конфигурацию, версии, hashes датасета/кода, план и состояние. `records.jsonl` дописывается с flush/fsync после каждой попытки. Resume отвергает изменение кода/конфига/данных, пропуски и дубли. Блокировка каталога предотвращает параллельную запись. Повреждённый JSONL не исправляется молча.

Для сравнения двух завершённых реальных прогонов с одинаковыми данными, ID и версией prompt:

```bash
python -m nir_eval compare runs/model_a runs/model_b --output runs/comparison
```

Команда не вызывает модели, проверяет покрытие и отказывает при смешивании контролей или дублировании попыток. Сравнение разных backend/размеров/квантования относится ко всей конфигурации, а не к одному из этих факторов.

## XLSX-модуль

```bash
python -m nir_eval spreadsheet inventory --dataset-root /path/to/all_data_912_v0.1 --out runs/sheet_inventory.json
python -m nir_eval spreadsheet evaluate \
  --dataset-root /path/to/all_data_912_v0.1 \
  --predictions-dir /path/to/predictions \
  --provenance model-inference --formula-policy strict --out runs/sheet_results.json
```

Имена выходов: `predictions/<task_id>/<case_index>_<task_id>_output.xlsx`. Автоматического fallback на исходный XLSX нет. По умолчанию формулы без доказанного пересчёта не засчитываются; `cached` требует явного выбора и доверяет кешу, который может быть устаревшим. Отсутствующие файлы и неоценённые случаи остаются в знаменателе. Проверяются только размеченные значения ячеек, не всё оформление, диаграммы или макросы. [Подробности](docs/SPREADSHEET_RU.md).

## Что ещё не готово

- Достаточная статистическая оценка нескольких сильных моделей на полном закрытом test после фиксации протокола.
- Проверенные русскоязычные офисные задания и оценка качества деловых текстов.
- Настоящий агент редактирования XLSX и доверенный пересчёт формул в изолированном LibreOffice/Excel.
- Контроль пользовательских расходов, multi-user UI, аутентификация, развертывание, production sandbox и управление персональными данными.
- Hosted-квантование неизвестно; reasoning-параметры нельзя приписывать модели без поддержки провайдера. Сравнение разных размеров модели/движков/квантования не изолирует эффект одного фактора.
- Бесплатные модели OpenCode **не вызывались**: сторонний прямой API не является поддержанным способом, а допустимость массового benchmark по условиям сервиса требует отдельного уточнения. Обходов нет.

## Отдельное приложение CPU / Colab T4

Два одинаковых prompts одного задания дополнительно измерены на CPU и Tesla T4. Это проверка скорости, **не новый полный GPU-прогон качества**. Native decode: 5.096→27.149 токенов/с (5.33×), prefill: 20.825→720.208 (34.58×). GPU и CPU сгенерировали разные ответы (100 против 99 токенов); меняются машина и сборка, поэтому это описательные коэффициенты на двух запросах, без доверительного интервала и гарантии доступности бесплатного T4. Основные 60 benchmark-попыток остаются неизменными.

Резюме: `runs/hardware_speed_comparison/README_RU.md`; raw evidence, оригинальный маленький Colab ZIP и offload log — в `evidence/performance/`. Проверка hashes, prompts и counters без модели/сети: `python scripts/audit_speed_probe.py`. Нативный log подтверждает 29/29 слоёв на GPU. Большие веса, wheel_check, .so и .venv в релиз не входят.
