# Реальные прогоны Promptfoo / OpenCode Go · 11 ноября 2026

**Сквозной бизнес-сценарий выполнен:** три выбранные модели ответили на одинаковые две синтетические задачи, отдельный GLM 5.3 выдал **6 из 6 валидных оценок**, сохранены ответы, время, токены, данные стоимости и бизнес-отчёт. Использован Promptfoo 0.125.1 через API OpenCode Go. Это небольшой интеграционный прогон, **не рейтинг моделей** и не оценка качества на реальных данных компании.

## Итоговый бизнес-прогон

Задачи: расчёт роста выручки и ответ по правилам возврата. Судья — `glm-5.3`, `temperature=0`, `max_tokens=8192`, разрешено одно дополнительное исправление невалидной структуры. Политика: качество не ниже 0,8, полнота оценок 100%, отсутствие ошибок генерации и обнаруженных критических ошибок. Денежный лимит и предел времени в этом выборе не заданы.

| Модель | Валидные оценки | Среднее качество, 0–1 | Среднее время solver, с | Среднее время solver + judge, с | Сообщённая стоимость solver + judge за обе задачи, USD |
|---|---:|---:|---:|---:|---:|
| GPT 6 Luna (`gpt-6-luna`) | 2/2 | 1,00 | 5,35 | 26,80 | 0* |
| Qwen 3.7 Plus (`qwen3.7-plus`) | 2/2 | 0,95 | 24,52 | 66,66 | 0* |
| GLM 5.3 Flash (`glm-5.3-flash`) | 2/2 | 1,00 | 4,01 | 37,52 | 0* |

Все три конфигурации прошли ограничения. Система сохранила **ничью по максимальному качеству** между GPT 6 Luna и GLM 5.3 Flash; единственный победитель не выбран. Разница на двух задачах не доказывает превосходство модели для бизнеса в целом.

Таблица времени измеряет вызов адаптера целиком, включая запуск холодного Node worker при первом запросе. Время судьи включает явно разрешённые исправления структуры. Поэтому эти числа нельзя считать чистым временем inference или выводом о скорости Promptfoo относительно другого транспорта.

*Ноль подтверждён API: для всех 18 запросов итогового этапа сохранены `cost_usd=0`, `cost_basis=provider_reported`, `billing_source=go`. Это сообщённая цена конкретных запросов в рамках Go, а не утверждение, что подписка бесплатна. `list_cost_usd` — отдельная справочная величина, её нельзя прибавлять как дополнительное списание. Неизвестная стоимость не заменяется нулём.*

## Проверка судьи и ограничения надёжности

Отдельная итоговая калибровка GLM 5.3 содержит **4 заранее размеченных синтетических ответа**: правильный и ошибочный ответ для каждой из двух задач. Обработаны **4/4**, согласие по прохождению и критическим ошибкам — **4/4**. Все четыре калибровочных оценки получены с первой попытки. Это авторские контрольные примеры, а не независимая сертификация или статистическая гарантия точности. [Сводка калибровки](../runs/promptfoo_go_final_20261111/calibration/summary.json), [оценки](../runs/promptfoo_go_final_20261111/calibration/records.jsonl), [разметка](../runs/promptfoo_go_final_20261111/calibration/labels.jsonl).

Предыдущая калибровка была существенно хуже: **3/6 валидных оценок**, три результата неизвестны. На двух ошибочных ответах API вернул некорректную структуру Chat Completions; ещё один вердикт содержал несовпадающий набор критериев. Все три валидные оценки относились к правильным ответам, поэтому согласие 100% среди них не доказывало способность обнаруживать ошибки. Неизвестные оценки не получили ноль или положительный результат. [Первоначальная сводка](../runs/promptfoo_go_20261111/calibration/summary.json), [подробные записи](../runs/promptfoo_go_20261111/calibration/records.jsonl).

Итоговая калибровка использует четыре примера из двух задач, а первоначальная — шесть из трёх. Также изменены настройки судьи. Поэтому улучшение нельзя приписать одной настройке или распространять на весь прежний набор.

В итоговом бизнес-прогоне судья потребовал **два дополнительных запроса** для исправления структуры: один при оценке Qwen, один при оценке GLM Flash. Эти запросы сохранены в `judge.attempts` и входят во время и учёт стоимости. Автоматические транспортные повторы отключены; исправление структуры было явно разрешено настройкой судьи.

## Проверка перехода на Promptfoo

До удаления прежнего Python-транспорта выполнен парный smoke-test MiniMax M3.1 Flash на двух одинаковых задачах с GLM 5.3 в качестве судьи:

| Транспорт | Валидные оценки | Среднее качество | Среднее время solver, с | Среднее время solver + judge, с |
|---|---:|---:|---:|---:|
| Прежний Python-транспорт | 2/2 | 1,000 | 2,93 | 31,79 |
| Promptfoo | 2/2 | 0,975 | 4,86 | 49,04 |

Обе конфигурации прошли заданные ограничения. Стоимость всех восьми запросов этого этапа по данным API — 0 USD с `billing_source=go`. Отдельные модельные ответы, оценки судьи, холодный запуск и внешняя задержка различаются; это подтверждение прохождения двух путей исполнения, а не контролируемый эксперимент об их сравнительной скорости или качестве.

## Неудачные подключения не скрыты

Первоначально DeepSeek V4.1 Flash и Muse Spark 1.3 Contributor вернули HTTP 400 в обоих путях исполнения. Два дополнительных диагностических запроса установили причины: **региональное ограничение** для DeepSeek и **ограничение настройки использования данных для обучения** для Muse. Это не ошибка 429 и не исчерпание квоты. Настройки аккаунта не менялись; ограничения не обходились.

В первом бизнес-прогоне подходящих конфигураций нет, качество и стоимость недоступных ответов остаются неизвестными. Числа времени этих ошибок не являются временем выполнения бизнес-задач моделью.
