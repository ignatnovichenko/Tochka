# Установка Tochka на Linux и macOS

## Быстрый старт

**Сначала установите Node.js 22.22.0 или новее и npm.** Убедитесь, что `node --version` и `npm --version` работают в этом терминале. Нужны интернет, `curl` и стандартные утилиты Linux/macOS. Установщик проверяет Node.js/npm до установки приложения и не загружает Node.js самостоятельно.

```bash
curl -fsSL https://raw.githubusercontent.com/ignatnovichenko/Tochka/main/install.sh | sh
```

После установки откройте новый терминал и введите `tochka`. Если хотите сначала посмотреть скрипт, скачайте `install.sh` на странице Releases, откройте его в редакторе и выполните `sh install.sh`.

Установщик 0.4.0 устанавливает релиз `v0.4.0` из GitHub. Он использует имеющийся uv или загружает uv 0.13.4 из официального источника Astral. uv подготавливает Python 3.11 и отдельное окружение приложения. Системный Python не изменяется; Git и OpenCode не требуются.

После установки пакета скрипт автоматически запускает `tochka setup`: зависимости Promptfoo 0.125.1 загружаются через npm по закреплённому lock-файлу, затем проверяется локальный runtime. При ошибке setup установщик завершается с ошибкой и не сообщает об успешном завершении; Python-пакет при этом уже может быть установлен. После исправления Node.js/npm или доступа к registry повторите `tochka setup` либо установщик.

Модельные запросы при установке не выполняются. После успешного завершения подключите ключ через `/keys` и создайте эксперимент через `/wizard`. Повторная проверка без установки: `tochka setup --check` или `/setup --check`. Просмотр сохранённых результатов и повторный отбор не требуют Node.js. [Подробнее о Promptfoo](PROMPTFOO_SETUP_RU.md).

Поддерживаемые архитектуры: x86_64 и ARM64. На macOS используются те же Python-модули; fcntl, POSIX-права и блокировки доступны на обеих ОС. Папка ключей по умолчанию на обеих системах — `~/.config/tochka`. Установщик не является `.app`/`.dmg` с графическим интерфейсом.

## Настройка PATH

uv добавляет папку команд в настройки вашей оболочки. Для текущего терминала установщик печатает полный путь к Tochka; для обычного запуска откройте новый терминал. Bash, Zsh и Fish обрабатываются механизмом `uv tool update-shell`.

Без изменения профиля оболочки:

```bash
sh install.sh --no-modify-path
```

После этого запускайте Tochka по напечатанному полному пути или добавьте каталог в PATH самостоятельно. Не запускайте установщик через sudo.

## Обновление и удаление

Повторный запуск актуального установщика обновляет приложение до закреплённого в нём релиза. Данные экспериментов, результаты и сохранённые ключи не удаляются. Для конкретного опубликованного релиза:

```bash
sh install.sh --version 0.4.0
```

Удаление приложения: `uv tool uninstall nir-eval`. Если uv был установлен загрузчиком и недоступен по короткой команде, используйте полный путь, напечатанный установщиком. Bootstrap uv находится в `$XDG_DATA_HOME/tochka/bootstrap` или `~/.local/share/tochka/bootstrap`. Отдельный runtime Promptfoo находится в `$XDG_DATA_HOME/tochka/promptfoo-0.125.1` или `~/.local/share/tochka/promptfoo-0.125.1`; удаление Python-пакета не удаляет этот каталог. Удаление приложения не отзывает API-ключи и не удаляет их локальное хранилище. Для ключей есть `/keys`.

## Отличия готовой установки от исходников

Обычная установка включает интерактивный CLI, демозадачи, API, ключи, отчёты и диагностику. Крупные исследовательские данные и исторические результаты находятся в репозитории/полном архиве. Модульные тесты и работа с исходниками требуют установки для разработки, описанной в README. После `pip install -e .` выполните `tochka setup` самостоятельно: pip не устанавливает Node.js или npm-зависимости.

В обычной установке `/doctor` выполняет диагностику и даёт рекомендации. Применение изменений к исходному проекту рассчитано на установку из клона через `pip install -e .`, где доступны исходники и `pyproject.toml`.

Установка не проверяет доступность вашей оплаченной модели: ключ, разрешённые модели, лимиты и условия подписки зависят от провайдера.

## Проверка совместимости

GitHub Actions запускает тесты, эталонные проверки и реальную установку в отдельное окружение на Ubuntu, macOS ARM64 и macOS Intel. Каждая установка проверяет запуск CLI и наличие демозадач. API-вызовы реальных моделей в этих проверках отсутствуют. Поддержка Linux ARM64 предусмотрена загрузчиком и Python-пакетом; отдельного ARM64 Linux-прогона CI пока нет.
