# Установка Tochka на Linux и macOS

## Быстрый старт

Версия 0.5.2 использует собственный Python-движок; Node.js/npm не нужны.


Нужны интернет и `curl`; Python вручную устанавливать не нужно. Установщик использует имеющийся uv или загружает uv 0.13.4 из официального источника Astral. uv подготавливает Python 3.11 и отдельное окружение приложения. Системный Python не изменяется; Git, OpenCode, Node.js и npm не требуются.

После публикации релиза 0.5.2 станет доступна установка:

```bash
curl -fsSL https://raw.githubusercontent.com/ignatnovichenko/Tochka/main/install.sh | sh
```

После установки откройте новый терминал и введите `tochka`. Внутри введите `/`, чтобы открыть меню действий с описаниями; `/run --help` покажет аргументы запуска. Установщик дополнительно печатает полный путь к команде.

Собственный движок входит в Python-пакет и использует стандартную библиотеку Python для HTTP-запросов и параллельного исполнения. Скрипт проверяет его через `tochka setup --check`. При ошибке проверки установщик завершается с ошибкой и не сообщает об успешном завершении; Python-пакет при этом уже может быть установлен. После устранения причины повторите установщик.

Модельные запросы при установке не выполняются. Подключите ключ через `/settings` → «API-ключи» и создайте эксперимент через `/experiment`. Повторная локальная проверка: `tochka setup --check` или `/setup --check`.

Поддерживаемые системы загрузчика: Linux (включая Arch Linux и Omarchy), macOS Intel и Apple Silicon; архитектуры x86_64 и ARM64. Системные пакетные менеджеры и `sudo` не используются. Установка на Alpine/musl отдельно не проверена. Папка ключей по умолчанию на Linux/macOS — `~/.config/tochka`. Установщик не является `.app`/`.dmg` с графическим интерфейсом.

## Настройка PATH

uv добавляет папку команд в настройки вашей оболочки. Для текущего терминала установщик печатает полный путь к Tochka; для обычного запуска откройте новый терминал. Bash, Zsh и Fish обрабатываются механизмом `uv tool update-shell`.

Без изменения профиля оболочки:

```bash
sh install.sh --no-modify-path
```

После этого запускайте Tochka по напечатанному полному пути или добавьте каталог в PATH самостоятельно. Не запускайте установщик через sudo.

## Обновление и удаление

Повторный запуск актуального установщика обновляет приложение до закреплённого в нём релиза. Данные экспериментов, результаты и сохранённые ключи не удаляются. Для конкретного опубликованного релиза:

```bash
sh install.sh --version 0.5.2
```

Удаление приложения: `uv tool uninstall nir-eval`. Если uv был установлен загрузчиком и недоступен по короткой команде, используйте полный путь, напечатанный установщиком. Bootstrap uv находится в `$XDG_DATA_HOME/tochka/bootstrap` или `~/.local/share/tochka/bootstrap`. Если вы обновлялись с 0.4–0.5, старые каталоги Promptfoo и Node.js могут оставаться в `~/.local/share/tochka`; новый движок их не использует и автоматически не удаляет. Удаление приложения не отзывает API-ключи и не удаляет их локальное хранилище. Для ключей есть `/settings` → «API-ключи».

## Отличия готовой установки от исходников

Обычная установка включает интерактивный CLI, демозадачи, API, ключи, отчёты и диагностику. Крупные исследовательские данные и исторические результаты находятся в репозитории/полном архиве. Модульные тесты и работа с исходниками требуют установки для разработки, описанной в README. После `pip install -e .` можно выполнить `tochka setup --check`; отдельные зависимости движка устанавливать не требуется.

В обычной установке `/doctor` выполняет диагностику и даёт рекомендации. Применение изменений к исходному проекту рассчитано на установку из клона через `pip install -e .`, где доступны исходники и `pyproject.toml`.

Установка не проверяет доступность вашей оплаченной модели: ключ, разрешённые модели, лимиты и условия подписки зависят от провайдера.

## Проверка совместимости

В локальных настройках GitHub Actions предусмотрены тесты, эталонные проверки и установка в отдельное окружение на Ubuntu, macOS ARM64 и macOS Intel. Проверка установки дополнительно скрывает Node.js/npm за неработающими командами: собственный движок не должен к ним обращаться. Статус проверки опубликованной версии доступен в GitHub Actions. API-вызовы реальных моделей в CI не выполняются. Отдельного ARM64 Linux-прогона CI пока нет.

## Обновление из CLI

В интерактивном режиме введите `/update`, либо выполните `tochka update` в терминале. Команда загружает официальный установщик из ветки main GitHub и запускает его без изменения настроек оболочки. Если raw.githubusercontent.com недоступен, используется официальный Contents API на api.github.com; при ошибке показывается конкретная причина. Ключи, эксперименты и результаты сохраняются. После обновления запустите Tochka заново. При ошибке установки выводится сообщение о неудаче; повторите команду после устранения причины.

Если локальная версия новее опубликованной, команда оставляет её на месте. Это защищает неопубликованные локальные изменения от отката к старому релизу.
